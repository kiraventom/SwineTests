# SwineTests

Симулятор [SwineBot](../SwineBot): гоняет бота по виртуальному времени, подсовывает
апдейты от шести тестовых пользователей с разными стратегиями кормления и проверяет,
что бот отвечает без ошибок. Telegram не трогается — все отправители замоканы.

## Запуск

Репозитории должны лежать рядом: `../SwineBot` — сам бот.

```bash
dotnet run -c Debug -- --days 200
```

| аргумент | по умолчанию | зачем |
|---|---|---|
| `--days <N>` | обязательный | сколько виртуальных дней прогнать (24 тика в день) |
| `--db <path>` | `~/.local/share/SwineTests/users.db` | своя база; файл пересоздаётся на каждом прогоне |
| `--achiev <path>` | `../SwineBot/Achievements/achiev_data.json` | данные ачивок |
| `--verbose` | выкл. | печатать текст каждого сообщения бота |
| `--no-slaughter` | выкл. | не забивать свиней каждые 60 дней |
| `--duel-chance <0..1>` | `0.02` | шанс на час, что пользователь вызовет кого-то на дуэль; `0` отключает дуэли |
| `--replay` | выкл. | реплей прод-беседы на 8 профилях вместо шести тестовых стратегий |
| `--consent <0..1>` | `0.55` | с какого шанса защитник соглашается (порог храбрости) |
| `--call-model nearest\|any` | `nearest` | `nearest` — цель из трёх ближайших по весу, `any` — случайный более тяжёлый (старая модель, давала пары «малыш против толстяка») |
| `--min-weight-ratio <0..1>` | `0` (выкл.) | явный запрет бить слишком лёгкого; в v3 не нужен — риск ограничен ставкой |
| `--stop-slaughter <день>` | `-1` (всегда) | перестать забивать с этого дня: так убийца «живёт с запаса» |
| `--duelists Имя,Имя` | все | кто вообще участвует в дуэлях |
| `--spoiler <владелец>` | выкл. | стратегия «сорвать разгон»: этот свин режет себя, когда конкурент подбирается к его весу |
| `--spoiler-share <0..1>` | `0.7` | с какой доли веса конкурента включается «срыв» |

**Переопределения настроек бота.** Флаги `--chance`, `--debuff`, `--no-glory`,
`--stake`, `--min-chance`, `--max-chance`, `--growth`, `--growth-k`, `--mod-fuel`,
`--elite-share`, `--heir-share` по умолчанию **не заданы**: харнесс берёт значения из
`DuelBalance`/`GrowthBalance`, то есть мерит ровно то, что поедет в прод. Действующие
значения печатаются в начале прогона (строка «=== Баланс») — по ним лог и привязывается
к конфигурации. Крутить их имеет смысл только для свипов вида «а что если».

Код возврата: 0 — все апдейты обработаны и все инварианты сошлись, 1 — есть провалы,
2 — неверные аргументы.

## Релизная проверка

```bash
./release-check.sh          # сценарии + 20 сезонов по 365 дней на дефолтах бота
./release-check.sh 40       # больше прогонов, если нужен узкий доверительный интервал
```

Скрипт собирает проект, гоняет сценарии, затем N сезонов реплея и печатает медианы
(`analyze-season.py`). Разрыв «бережливый — убийца» шумит: sd ≈ 5–7 тыс. кг, поэтому
20 прогонов различают только разницу больше ~3 тыс., и выводы вида «0.4 лучше 0.25»
на такой выборке делать нельзя. Число боёв в сводке — за год.

Сборка: если бот уже собирался **не через** симлинк `../SwineBot` (например, напрямую
в клоне репозитория), `dotnet build --no-incremental` здесь падает с `CS0006` —
MSBuild ведёт один проект по двум разным путям. Лечится `rm -rf ../SwineBot/obj
../SwineBot/bin` и повторной сборкой.

## Что делает прогон

- Шесть пользователей в одной группе (`Chat.Id = -1337`), у каждого свой свин.
  TelegramId детерминированный: `1000 + (int)strategy`, чтобы прогоны были сравнимы.
- Каждый тик (час) пользователь решает, кормить ли свина по своей стратегии:
  `RegularNoOverfeed` (раз в ~25 ч), `Overfeed12/8/6/4` (перекорм соответственно),
  `Overfeed12Then6` (12 ч, а после ачивки Overfeed 31 — 6 ч).
- Каждые 60 дней (кроме `RegularNoOverfeed`) — `/slaughter yes`.
- В конце: сводка по свинам, ачивки по типам, `/top`, картинка `/history` и инварианты.

## Дуэли

Прогон состоит из двух частей.

**1. Сценарии** (`DuelScenarios`) — на двух пользователях, до длинной симуляции, на
чистой базе. Проверяют формулы (`DuelResolution`: шанс, ставка, штраф, полы по весу,
сохранение суммы) и весь путь вызова: сообщение с кнопками и `MessageId`, блокировка
защитника с напоминанием и ссылкой `t.me/c/...`, запрет отвечать за защитника,
принятие вызова с переносом веса и записью `DuelResult`, повторное нажатие,
кулдаун у обеих сторон, отказ со штрафом в пользу вызывающего, истечение по TTL,
нажатие по просроченному вызову, и то что отказы не попадают в статистику `/info`.
После сценариев база чистится (`DuelRequests`, `DuelResults`, `Feeds`, `WeightLosses`,
`Achievements`, `Slaughters`, вес в 1 кг), чтобы симуляция началась с нуля.

**2. Симуляция** — каждый час каждый пользователь с шансом `--duel-chance` вызывает
случайного подходящего противника (не себя, вес > 1, без висящего вызова, не на
кулдауне). Противник отвечает, когда его следующее действие упирается в напоминание:
кнопку жмёт его же владелец, 70% — принять. Ответы идут через настоящий
`CallbackQueryHandler`, поэтому проверяется и коллбэчный путь.

### Правила v3 (2026-11-19)

- Шанс защитника: `50 + 0.6·(доля веса − 50) − 5 (инициатива атакующего) + 2 п.п.·(слава)`, кап 10/90.
- Ставка: **5% от более лёгкого**, без абсолютного капа — один бой не решает год.
- Слава: +1 победа, +2 апсет (вдвое легче победил), −1 отказ; капы ±5, не затухает;
  даёт шанс, до +15% к кормёжке и «без очереди» для свина с минусом.
- Никакого страха-голода и обесценивания забоя: отказ платится только славой.
- Лимиты: 24 ч на вызов на свина, 24 ч на беседу, 48 ч на защитника (скип для труса),
  72 ч на пару, TTL 12 ч.
- Рост от забоёв — не вечный пассивный доход, а **разгон с запасом**: забой добавляет
  запас, множитель считается от него (`1 + k·√запаса`, k = 0.02, банк 10 000 → ×3.00),
  и тратится, когда свин тяжелее половины веса лидера беседы (`FuelPerBonusKg` = 2 кг
  запаса на кг бонусной массы). Наследник получает 40 % запаса, но не меньше прежнего:
  забой не должен быть наказанием. Все числа — в `GrowthBalance`, действующие значения
  печатаются в шапке прогона.

Итог года на реплее (20 прогонов на текущих числах): 80 боёв, 18 % отказов, 14 % боёв
с двукратной разницей, медиана разрыва «убийца − бережливый» −1 862 кг при sd 6 907,
обнулений нет, убийца ни разу не ниже 10 000 кг.

Что показывает прогон на 200 днях (`--days 200`, дуэли включены):

| стратегия | вес | кормёжек | дуэли W/L | отказов |
|---|---|---|---|---|
| RegularNoOverfeed | 1820 | 140 | 64/23 | 35 |
| Overfeed8 | 1062 | 45 | 6/0 | 5 |
| Overfeed12 | 740 | 33 | 2/5 | 5 |
| Overfeed6 | 564 | 56 | 6/5 | 7 |

перетекает к остальным. Кормёжек у остальных тоже становится меньше: пока висит
вызов, кормить нельзя, и окно кормления теряется.

## Инварианты

Проверяются в конце прогона, числа случайны, поэтому проверки качественные (числа в
таблицах выше сняты на старых правилах и не перепроверялись после v3):

- вес свина не уходит ниже 1 кг;
- стратегия без перекорма не получает ачивку Overfeed;
- `Overfeed4` блюёт чаще, чем `RegularNoOverfeed`;
- спокойное кормление набирает вес лучше жадного (только при `--duel-chance 0`: дуэли перетасовывают вес);
- забои идут ровно раз в 60 дней (или их нет с `--no-slaughter`);
- у каждой дуэли ставка одинаковая с обеих сторон и не отрицательная;
- если дуэли включены, они действительно шли;
- не осталось вызовов старше TTL;
- `/history` отдаёт непустой PNG.

## Что уже вскрылось на прогонах

- Забой свина **удаляет** его вместе с кормёжками (каскад) и создаёт нового с весом 1.
  Поэтому `/history` показывает только текущую жизнь: без `--no-slaughter` график
  у забивающих стратегий обрывается на 60-м дне.
- Эффект ачивки `NoOverfeed` усиливает luck, а `amount = MAX_FEED_AMOUNT * luck`,
  поэтому средняя прибавка за кормёжку у спокойного свина может быть больше 20 кг.
- Кормить чаще, чем раз в ~8 часов, смысла нет: `Overfeed6` и `Overfeed4` тонут в
  throwup'ах (на 200 днях — 1177 и 22 кг против ~4300 кг у остальных).
